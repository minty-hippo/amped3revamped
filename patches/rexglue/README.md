# ReXGlue SDK fixes

`setup.ps1` (and `setup.sh` on Linux) applies these to the SDK before building it. `0001` and `0002` come from
[3on3NHL-recomp](https://github.com/Wndwsqrrl/3on3NHL-recomp) (MIT, see
`LICENSE-3on3NHL-recomp.txt`) and target the same SDK commit (`c94f5eb`).

| Patch | Fixes |
|---|---|
| `0001-input-system-lock.patch` | `InputSystem` has no locking; games that poll controllers from two threads can hang or crash while devices are re-enumerated. The port's options menu also reads controllers from its own thread, so this one is required. |
| `0003-fpscr-keep-exceptions-masked.patch` | Written for Amped 3. Crash about 2 s into loading with exit code `0xC000008F` (floating-point inexact result) and no log message. The cached FP control word is 0 on contexts `InitHost` never seeded; when the game sets a rounding mode, writing that word back unmasks every host FP exception. `setcsr` now always keeps the exception masks set. Needs a full rebuild (it's in a header the generated code uses). |
| `0004-tfetch1d-keep-second-coordinate.patch` | Written for Amped 3. Title UI, menus, HUD and map draw garbled after the intro. The game issues `tfetch1D` with an explicit second coordinate (src swizzle `.xyz`) against a 2D fetch constant; the translator kept only X, so it sampled the first row of the texture. Such fetches are now translated as 2D (a true 1D texture is unaffected: Y can only select row 0). Setting `gpu_tfetch1d_keep_y` (default on). Same root cause as [xenia-canary/game-compatibility#583](https://github.com/xenia-canary/game-compatibility/issues/583). |
| `0002-codegen-vpk-unsigned-alias.patch` | Recompiled `vpkuwus`/`vpkuhus` corrupt their result when the destination is also a source (striped green/orange video in VP6 movies). |
| `0005-vulkan-log-render-target-path.patch` | Logs which Vulkan render-target path is in use (`VulkanRenderTargetCache: requested path ...`) and accepts `fbo` as an explicit value. Behavior is unchanged: empty (Automatic) means host render targets, `fsi` means fragment shader interlock. |
| `0006-vulkan-resolve-write-barrier.patch` | Written for Amped 3. Short one-pixel-high horizontal streaks on Vulkan (FMVs, gameplay, map screen) that Direct3D 12 doesn't show. Resolves (EDRAM -> guest memory copies, done by a compute shader) marked their writes to the shared-memory buffer as *reads* in the following pipeline barrier, so the writes were never made available to the texture loads that read the resolved image. GPUs with coherent caches hide this; Intel shows stale 64-128-byte runs. |
| `0007-display-locked-vblank.patch` | Written for Amped 3 (native-renderer step 1). The guest's 60 Hz vertical blank came from a free-running timer polled every millisecond, so it drifted against the monitor: a frame was shown twice or skipped every few seconds, and each vblank could be up to 1 ms late. New setting `vblank_source` (default `display`): the vsync thread waits for the real vertical blank of the monitor the game window is on (DXGI `WaitForVBlank`), measuring its rate first. A 120 Hz monitor marks every second refresh; rates that don't divide to 60 Hz (75, 144) and non-Windows builds keep the timer. Adds `src/graphics/display_vblank*`. |
| `0008-external-guest-output.patch` | Written for Amped 3 (native-renderer step 4, stage 3). Lets the application supply the image shown in the window. `Presenter::SetGuestOutputExternal(true)` makes the emulated GPU's swap stop refreshing the guest output, and `RefreshGuestOutputExternal` refreshes it from the application's own frame (the native renderer preview, setting `native_renderer`). A mutex keeps the two producers apart while switching. No behavior change while the setting is off. |
| `0009-host-drawing-switch.patch` | Written for Amped 3 (native-renderer step 5). `CommandProcessor::SetHostDrawingEnabled(false)` stops the emulated GPU's host work while the native renderer draws the frames: every PM4 packet still runs (registers, fences, interrupts, waits, shader loads), but draws, resolves and swaps return at once and occlusion queries report the fake sample count. The change takes effect at the next swap packet, so a frame is never half drawn. Header change: needs the SDK rebuilt (`setup.ps1` without `-SkipSdk`). No behavior change unless the application switches it off. |
| `0010-vulkan-external-memory.patch` | Written for Amped 3 (native renderer). Enables `VK_KHR_external_memory_win32` / `_fd` on presentation devices that support them (`VulkanDevice::Extensions`), so the presenter can import the image the native renderer draws on its own Vulkan device and copy it on the GPU instead of through the CPU. Header change: needs the SDK rebuilt. |
| `0011-swap-gamma-snapshot.patch` | Written for Amped 3 (native renderer). `CommandProcessor::GetSwapGammaRamp` returns the gamma ramp (256-entry table and PWL) as it was at the last swap packet, copied on the command processor thread under a mutex. The native renderer applies the ramp from another thread; reading the live registers there raced with the game rewriting them and could pick up a scrambled ramp (psychedelic colours that stayed until the renderer was reset). Header change: needs the SDK rebuilt. |
| `0012-integer-scaling.patch` | Written for Amped 3. New `present_effect` value `integer`: the picture is shown at the largest whole multiple of its size that fits the window, centered, with nearest-neighbour sampling (the Vulkan and Direct3D 12 presenters pick the point sampler). Falls back to the normal fit when even 1x doesn't fit. Header change: needs the SDK rebuilt. |
| `0013-live-display-settings.patch` | Written for Amped 3. The output effect (`present_effect`, CAS / FSR sharpness, dithering) and `vblank_source` apply without a restart. The presenter rebuilds its paint configuration when one of them changes, and the vblank thread switches between the monitor and the timer. Integer scaling becomes a proper effect (`Effect::kInteger`, drawn by a `kNearest` pass with its own nearest-sampler descriptor sets / root signature in the Vulkan and Direct3D 12 presenters), replacing 0012's start-up sampler choice. Header change: needs the SDK rebuilt. |
| `0014-posix-thread-exit-without-unwind.patch` | Written for Amped 3 (Linux). Abort (`SIGABRT` in `__gxx_personality_v0` under `pthread_exit`) a few seconds after the intro starts, when the game ends a thread with `ExTerminateThread`. On POSIX a thread ending itself called `pthread_exit`, which unwinds the stack and calls `std::terminate` when it meets a frame it can't unwind through (a `noexcept` function or recompiled guest code). The thread now jumps back to its start routine instead (`sigsetjmp`/`siglongjmp`), like `ExitThread` on Windows, which doesn't unwind. Windows builds are unaffected. |
| `0015-audio-force-stereo.patch` | Written for Amped 3 (Linux handhelds). Cutscene and movie dialogue silent while music and in-game speech play. The game mixes cutscene dialogue into the 5.1 center channel; speakers that report 6 channels but only play the front pair drop it. New setting `audio_force_stereo` (options menu: Audio > Stereo mix, applies at once): the stereo fold (center and surrounds into left and right) goes out on the front pair of the 6-channel stream. Off by default; no change while off. |
| `0016-vblank-timer-off-windows.patch` | Written for Amped 3 (Linux). Uneven frame pacing: with `vblank_source = display` (the default) the vblank thread looked for the game window every half second for the whole session, because the non-Windows stub never reported it found, and every attempt restarted the vblank timer, so a guest vblank came late twice a second. The stub now reports the window found, so the thread settles on the timer after the first attempt (`vblank: monitor timing unavailable, using the timer`). Windows unchanged. Applies after `0007`, which adds the file. |
| `0017-lean-emulated-gpu.patch` | Written for Amped 3 (native renderer). Lets an application that draws the frames itself start the emulated GPU lean. `ReXApp::OnWantShaderStorage()` (default true) can skip loading the persistent shader storage at launch, which otherwise translates and creates every stored shader and pipeline before the game starts; shaders then compile on demand if the emulation draws after all. `rex::system::SetDrawResolutionScaleCap()` (in the runtime, since the GPU plugin is a separate library) caps the draw resolution scale for this run without touching the settings (the EDRAM buffer is 10 MB times the scale squared, up to 90 MB at 3x). The port uses both when the native renderer is on at launch (setting `emulated_gpu_lean`, default on). No change unless the application asks. Header change: needs the SDK rebuilt. |
| `0018-timer-queue-no-spin.patch` | Written for Amped 3 (performance). The SDK's timer thread (`rex::thread::TimerQueue`) took new timers through a spin-waiting ring buffer and kept about 10% of a core busy (performance trace, Windows). New timers now come through a mutex; the thread sleeps until a timer is added or the next one is due, on a condition variable (Linux, macOS) or, on Windows, a high-resolution waitable timer plus an event, since Windows rounds condition variable timeouts to the system timer tick and the kernel's 1 ms timestamp timer (`KeTimeStampBundle`) must keep its rate. (A first version polled the last millisecond, which with that 1 ms timer meant polling all the time: a whole core.) |
| `0019-gpu-event-write-hook.patch` | Written for Amped 3 (experimental branch, native renderer). `rex::system::SetGpuEventWriteHook()` registers a function the command processor calls before an `EVENT_WRITE_SHD` packet stores its value (physical address, value before the byte swap). It may block, which holds the emulated GPU at that packet. The port uses it to hold Direct3D's fences until its recorder thread has read the memory the draws before each fence use (setting `native_deferred_naming`). No change unless the application sets a hook. Header change: needs the SDK rebuilt. Applies after `0017`. |
| `0020-gpu-packet-hook.patch` | Written for Amped 3 (experimental branch, performance trace). `rex::system::SetGpuPacketHook()` registers a function the command processor calls with each packet header it executes; the port's performance trace sets it while recording and lists what the command stream still carries. Unset, it costs one atomic load per packet. Header change: needs the SDK rebuilt. Applies after `0019`. |

Drop a patch once an SDK release includes the fix (upstream: rexglue-sdk#364, #426).
